# OCTO-457 CLI sidebar integration

Implement the [OCTO-457 scheme](https://im.deepminer.com.cn/d/d_a4bfb28f541a67b77da116b7)
through six distinguishable `server sidebar` commands. Preserve every existing
command and its route, schema, authentication and output behavior. The product
rules remain in the backend; the CLI is transport, validation and formatting.

## Contract

| Command after `octo-cli server` | Method and path after `/api/v2/cli` |
| --- | --- |
| `sidebar list` | GET `/sidebar/conversations` |
| `sidebar follow <channel-id>` | PUT `/sidebar/conversations/{channel_id}/follow` |
| `sidebar mute <channel-id>` | PUT `/sidebar/conversations/{channel_id}/mute` |
| `sidebar move <channel-id>` | PUT `/sidebar/conversations/{channel_id}/category` |
| `sidebar mark-read <channel-id>` | POST `/sidebar/conversations/{channel_id}/_mark_read` |
| `sidebar category delete <category-id>` | DELETE `/sidebar/categories/{category_id}` |

The accompanying Server adapter reuses the six native handlers/services, uses
the existing independent Auth SDK router, and fixes the actor to the verified
Token owner and Space. It rechecks active Space membership without caching.
`im.sidebar:read` grants the personal list including visible message previews;
`im.sidebar:write` grants follow/mute/category changes and group-wide read clear.
The catalog entries and target Token grants must be provisioned before rollout;
they are not implied by installing the CLI or by old group/message permissions.

Responses preserve one backend `data` envelope and are emitted in the normal
CLI success envelope without another nested `data`. The list has no pagination.
Mutations never retry automatically, including raw `api` calls matched to the
registry. Old commands are never silently redirected to sidebar operations.

## Acceptance

- Real generated commands send all six exact paths with Bearer authentication
  and no caller-selected Space header; existing operation definitions stay intact.
- Explicit boolean false survives flag parsing. Required nullable category IDs
  accept a present JSON null, reject omission/empty strings, and preserve enum,
  const and type constraints on unrelated fields.
- Read targeting, complete child IDs, category deletion and group-only read clear
  preserve the native contract. No pagination flags appear.
- Unknown/invalid request fields are refused locally where the schema expresses
  the constraint; conditional target pairing remains validated by the backend.
- Lost mutation responses report an unknown outcome after one attempt; no
  automatic fallback to old routes, old credentials or another identity.
- CLI help/schema, raw API and MCP exec expose the same registered contract.
- Unit/race suites, vet, build and relevant lint/API checks run with recorded
  exit codes. Review the cumulative candidate three times and fix confirmed
  issues before publication. Author checks are separate from independent approval.
